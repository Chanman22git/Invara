§1 · Summary

What this is

The Lineage Proof dashboard answers one question about a fleet of production AI agents: is each capability behaving reliably? — did it take the same path it took before, run the steps it is required to run, and stay inside its cost norms. It reads this entirely from traces the agents already emit; it does not re-run agents to score them.

The unit of measurement is the leaf — a single intent the agent handles (e.g. Refund Eligibility, Delivery Status). Leaves roll up into capability levels and ultimately the agent. Every leaf is described by three structural signals plus a cost tripwire, and the product’s core design commitment is that these are never averaged into a single health score.

§2 · Scope

What it measures — and what it deliberately does not

In scope
Reliability: same path taken
Required steps actually ran
Cost within established norms
Drift away from a leaf’s own baseline
Invariant / policy-step violations
Out of scope
Correctness of the answer
Safety / harm evaluation
A single rolled-up “health score”
Re-running agents to grade them
User-satisfaction or quality ratings

A leaf reading green means it did the same thing, ran its steps, and stayed in budget. It does not claim the agent gave a correct or safe answer — that boundary is restated to the user on every leaf-detail screen.

§3 · Measurement model

Four signals, read independently

Each leaf carries three structural tiers and a cost tripwire. They answer different questions and are never collapsed into each other. A leaf can be green on three and broken on the fourth — that is the whole point.

Tier 0
cost
Cost / health tripwire
A smoke alarm, not a diagnosis — kept out of the grid. Watches the residual: actual cost minus the cost expected given context. A high residual is the looping signal, distinct from a leaf that is simply expensive. The only sensor that catches a retry spiral the structural tiers are blind to.
Tier 1
consist.
Consistency
A path-concentration percentage, read as a flag — conditioned on declared world-state features. A low value can only mean “investigate,” never “fail”, because unlogged world-state understates true consistency. Explained-variation tells the user whether spread is real-world branching or genuine wobble.
Tier 2
drift
Drift
The movement, not the level. A static 78% is shruggable; a step-down from 94% to 78% is not. Drift annotates the causal event (a deploy, a skill or KB version bump) on the timeline, so the change is tied to its cause before any invariant is breached.
Tier 3
invariant
Invariants
A violation rate, trusted like a defect count: did a required step run before the consequential action. Surfaces the money quadrant — a leaf that is highly consistent and violating, i.e. reliably doing the wrong thing. This state is invisible to consistency alone, and is the reason the tiers must stay separate.
Gate
The intent classifier gates everything. Every per-leaf number inherits the routing noise of the classifier that sorted traces into leaves. When classifier reproducibility falls below the trust threshold, all per-leaf numbers are dimmed and marked low-confidence until the gate clears. Fix the classifier before trusting the grid.
OQ-1
Exact formulae and thresholds for each tier (consistency conditioning, drift detection, the classifier trust gate) are not pinned in this draft. Confirm whether they belong in this PRD or a separate measurement spec.
§4 · Screens

Two screens, one drill path

The product is a fleet overview that drills into a single leaf. There is no third level: branches and traces live inside a leaf, never as their own nodes.

Screen A Fleet overview
Scope bar & filters — agent / team / org selectors and a 24h · 7d · 30d window.
Classifier gate banner — shown only when reproducibility is below threshold.
Stat tiles — classifier reproducibility, leaves measured, needs attention, new leaves (7d), open tripwires.
Capability tree — levels and leaves, each leaf showing its three-tuple + tripwire count; level rows roll up to their weakest child.
Cost / intent panel — residual per leaf, flagging looping cost distinctly from expensive-by-design leaves.
Needs attention — ranked queue of where to look first.
Screen B Leaf detail
Header — name, traffic, stakes, and current state.
Path view — the dominant skeleton and the diff come before the consistency number; dropped steps shown struck-through; distribution over skeletons.
Three-tuple — T1 / T2 / T3 as three independent readouts, each with its own reading rule.
Tier 0 cost block — visually distinct from the grid; flagged traces with a replay drill-down.
Leaf switcher + scope reminder — move between leaves; restate reliability ≠ correctness.

The agent / team / org / window filters are present in the mock but not yet wired. Confirm what each filters, whether all four ship in v1, and whether there is a cross-agent rollup above the single-agent tree.
§5 · Functional requirements

What the product must do

A · Fleet overview
FR-1
Capability tree of every measured leaf, grouped by capability level.
FR-2
Each leaf shows the full three-tuple plus tripwire count, never a single collapsed score.
FR-3
Level rollups display the weakest-link child (worst severity, then worst invariant, then lowest consistency) — not an average.
FR-4
Branches are never nodes — they exist only inside leaf detail.
FR-5
Header stat tiles: classifier reproducibility, leaves measured, needs attention, new leaves (7d), open tripwires.
FR-6
“Needs attention” ranks by severity then stakes — never by traffic volume.
FR-7
Cost panel surfaces residual, flagging high residual (looping) distinctly from a leaf that is legitimately expensive.
B · Classifier gate
FR-8
A classifier-reproducibility gate sits above all per-leaf numbers. Below threshold, every per-leaf number is dimmed and marked low-confidence.
FR-9
The gated state is previewable on demand so reviewers can see the low-confidence board before it happens.
C · Leaf detail
FR-10
Leaf detail leads with the path and the diff before showing any number.
FR-11
Dropped or missing skeleton steps are shown struck-through with a note on when and why they left the path.
FR-12
T1 / T2 / T3 are three independent readouts, never averaged; each carries its own reading rule. A low T1 can only invite investigation, never fail a leaf.
FR-13
T2 annotates the causal event (deploy, skill/KB version change) on its timeline.
FR-14
T3 flags the money quadrant — consistent and violating — explicitly.
FR-15
Tier 0 cost is kept visually out of the grid and lists flagged traces with a replay drill-down.
FR-16
A leaf switcher moves between leaves without returning to fleet.
D · Honesty & data integrity
FR-17
Below the traffic floor, show a blank, never a fabricated number — but still surface high-stakes low-traffic leaves rather than hiding them.
FR-18
All numbers derive from existing traces; the agent is never re-run to measure it. Replay is an explicit, separately-triggered drill-down.
FR-19
The dashboard displays its own limits — a persistent caveats strip naming what the numbers cannot tell you.
OQ-3
No alerting requirement is stated. Decide whether an open tripwire or a new money-quadrant leaf pages someone, or whether the product is dashboard-only in v1.
§6 · Acceptance scenarios

Five cases the product must get right

These are the canonical leaves the model is designed to expose. If the dashboard handles all five honestly, the design holds.

Refund Eligibility money quadrant
Consistency reads 99.4% while a required window-check, dropped after a skill update, is now skipped on 100% of traces. The product must show a violating leaf that consistency alone calls perfect.
Refund Processing drift event
The dominant path fell 94% → 78% when a policy KB version shipped. The product must tie the step-down to its deploy, and treat the movement — not the 78% — as the signal.
Escalation / Handoff cost tripwire
All three structural tiers read green while a retry spiral burns 4–6× expected tokens on the same skeleton. Only the Tier 0 tripwire can see this; the product must make that the visible alarm.
Availability n too low · high stakes
140 traces over 7 days is below the traffic floor. The product must show a blank — not a fabricated 100% — yet still surface the leaf because its stakes are high.
Delivery Status false alarm
A 70% consistency looks alarming but, conditioned on carrier status, resolves to a legitimate world-state branch. The product must let amber mean “investigate” and let the investigation end in “fine.”
§7 · Data model

The leaf object

Every leaf the dashboard renders is one record with this shape. Levels reference leaves by id; this is the contract the data pipeline must satisfy.

Field
Meaning
id, name, level
Identity and capability grouping.
traffic, stakes
Trace count in window; 1–5 stakes weight.
state, reason
Roll-up severity + the named case it represents.
t1, t1feature, t1explained
Consistency %, its conditioning features, explained-variation.
t2, series, event
Drift direction, timeline, annotated causal event.
t3, predicates
Violation rate + per-invariant predicates (money flag).
skeleton, dist
Dominant path (with missing steps) + distribution over skeletons.
cost{ }, trips
Avg / expected / residual, flagged traces, open tripwire count.
OQ-4
How are stakes, t1feature conditioning sets, and invariant predicates authored — manually per leaf, or harvested from policy? Who owns keeping them current?
§8 · Stated limits

What the product admits it cannot do

C1Tier 1 may read undramatically green — strict skill/KB guidance can push consistency to ~95%+ with dull residual.
C2Tier 1 feature sets and Tier 2 thresholds are tunable inputs, not fixed constants.
C3Tier 3 invariant coverage is harvested from policy and still expanding; cost-anomaly tuning is in progress.
